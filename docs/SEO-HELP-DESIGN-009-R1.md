# Own-brand Help correction

The user rejected the initial reference-led visual design. This revision keeps information architecture, not the reference composition.

Design input: the existing mobile app's LoginScreen uses WarmAuthChrome and the warm palette in OrderManagement/src/constants/designSystem.ts. No React Native source was modified.

The web treatment uses its soft-peach #FFF6EE canvas and translucent #FFD1B0 circles, warm-brown secondary text and an accessible darker orange for text links. A wordmark and orange dot replace the generic square badge. The homepage is a split introduction with three real starting articles, followed by a two-column numbered directory rather than three-column cards. Article pages use a warm outer canvas and a light reading panel, keeping desktop navigation and mobile article selection.

All 100 article records, routes, instruction steps and verification boundaries remain unchanged. No new dependencies, external assets or invented support capability. Tests include palette presence, own-composition structure and six normal-text contrast combinations at least 4.5:1, alongside the existing 500-page release checks.

Build/static/HTTP evidence does not constitute rendered desktop/mobile acceptance. Browser access remains unavailable; preview is supplied to the user. No push or deployment.
